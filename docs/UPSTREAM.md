## Rebase procedure

1. Pick the new Mac Stable tag from chromiumdash. Verify patches before
   changing the installed pin: `TAG=<new> scripts/verify_patches.sh`. A
   failure means a patch needs refreshing against that tag; keep it minimal.
2. Inspect and preserve the checkout's tracked changes with a named stash.
   Fetch and check out the new tag, then run `gclient sync -D`. Do not pop
   the old applied patches onto the new source.
3. Update `UPSTREAM_PIN` to the checked-out tag and commit. From this repo,
   run `scripts/apply_overlay.sh`; in the Chromium checkout, run `gn gen`,
   `gn check out/Modal '//chrome/browser/ui/modal_browser/*'`, and build
   both `chrome` and `browser_tests`. Stop on any failure. The complete
   command blocks are in `CHROMIUM_UPDATE.md`.
4. Re-read the APIs listed in `ARCHITECTURE.md` ("Chromium entry points
   used"). `BrowserWindowInterface::OpenGURL` is marked for removal upstream.
5. Run `scripts/check.sh`, then `scripts/run_browser_tests.sh` (our suite)
   and `scripts/run_browser_tests.sh 'BrowserViewTest.*:BrowserCommandsTest.*:BrowserCommandControllerBrowserTest.*'`,
   then `scripts/run_browser_tests.sh 'FindInPageControllerTest.*'`.
   The runner adds `--modal-browser-upstream-defaults` for upstream suites
   and a desktop-sized window only for Find tests; DevTools tests must keep
   their default/restored bounds. Also run the smoke tests in `TESTING.md`.
6. Record the build and results, then commit the pin, patch/API refreshes
   and accompanying documentation as "Rebase onto <version>".

Follow Stable, not `main`: Stable is what receives security fixes, and the
fork must track it.

## Security responsibility

Before any public build:

* Track Chrome Stable releases and their security notes; rebase within days
  of each Stable security update, faster for in-the-wild exploits.
* Keep security-sensitive changes minimal. The native blocker requires
  explicit `//content` and `//third_party/blink` hooks for worker responses,
  document lifecycle and memory-cache policy; patches 0014–0031 document
  this exception to the original UI-only boundary. Do not weaken sandbox,
  network security or permission checks. Keep each hook covered by native
  tests and repeat those tests after every Chromium update.
* Turnaround target once there are testers: a rebased, tested build within
  3 days of a Stable security release, within 24 hours when Google marks a
  fix as exploited in the wild. `scripts/check_upstream.py` detects them;
  builds reach testers by hand, for now.
* Never ship with sandbox, site isolation, Safe Browsing interstitials or
  permission checks weakened.
* Own branding, bundle ID and signing identity; no Google Chrome trademarks
  or assets. Both build configs set `branding_file_path` to Merlin's
  `BRANDING` (overlay/chrome/app/theme/merlin) and build without
  proprietary codecs or Widevine. Patch 0004 makes the Mac icon follow that
  file, names the product in `chromium_strings.grd` and gives the profile
  its own folder (`CrProductDirName`); patch 0007 renames the product in
  the remaining desktop string files (see the inventory).
* Google APIs and Chrome Sync are not available to forks by default
  (chromium.org/developers/how-tos/api-keys); nothing here depends on them.
